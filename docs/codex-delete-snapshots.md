# Codex 删除前快照

Codex 单条、批量、family 和历史分支删除共用后端门禁：先确认写入者停止，捕获删除前的数据，发布并重新读取 manifest 与全部内容进行验证，再执行删除。快照失败不允许降级为直接删除，也没有跳过快照的开关。

## 保存位置与内容

桌面和 WebUI 使用设置中的备份目录；CLI `family delete-branch` 支持 `--backup-dir`，未指定时使用原有默认备份目录。快照位于其下 `codex-delete-snapshots/delete-<时间>-<随机标识>/`，与普通备份分开。一次物理删除批次共用一份快照，返回的 `snapshot_path` 或失败消息给出路径。后续删除失败时仍保留已经完成的快照。

保存范围是本次删除的恢复材料：

- 实际待删除的所有 rollout，包括归档、重复副本和别名文件，保持原始字节。
- 原始 `session_index.jsonl`、`session_family.json`、`archive_ledger.json`、`.codex-global-state.json` 和已有 `history.jsonl`，记录文件原本缺失的状态。
- 完整 `state_5.sqlite`、已有 `logs_2.sqlite`、`thread_history_1.sqlite`、`sqlite/codex-dev.db` 和 `sqlite/codex-thread-summaries-dev.db`。整库保存可保留关系边、BLOB、未知字段和共享元数据，不读取认证配置或其他未列出的文件。

这些全库副本包含未选中会话的元数据，但只复制待删除的 rollout。因此它不是完整 Codex home，也不是可迁移会话包；普通备份列表不会把它当作普通会话导出显示。当前不自动清理快照，没有压缩、去重或保留策略；整个相关数据库的大小会影响空间和耗时。

## 校验与隔离恢复

在 Codex「备份 → 删除前快照」中查看快照。删除成功提示的「查看快照」可直接定位本次快照；列表展示来源、会话数、文件数、声明大小和读取状态，详情展示会话 ID、文件清单，以及复制路径和打开目录入口。单个损坏或未完成包不会遮住其他可读快照。

列表和详情只检查元数据及文件存在状态，不把快速读取标为完整校验。「重新校验」检查全部内容；「校验并恢复」要求选择已有父目录、填写新目录名称，并在恢复时再次完整验证。桌面选择器可选目录，WebUI 使用服务所在电脑的路径。已有目标拒绝覆盖，失败显示原因，修正目标后可重试。

页面显示操作进度和带时间的结果。最近一次校验与恢复结果保存在当前浏览器的本地存储中，清除浏览器数据后会丢失；它不是跨设备审计日志。重新打开、刷新或切换快照后，历史成功不会变为当前「校验通过」。恢复目录可从完成结果或历史记录打开。

使用删除结果中的实际快照目录：

```sh
cc-sessions delete-snapshot verify --path "<快照目录>"
cc-sessions delete-snapshot restore --path "<快照目录>" --output "<尚不存在的隔离目录>"
```

恢复目标的父目录必须已存在；目标不能位于原 Codex 数据目录或快照内，不能覆盖或合并已有目录。恢复前完整验证，恢复后重新核对每个文件的长度和 SHA-256，并对 SQLite 执行 `integrity_check`。只有全部成功后才写入 `agentvault-delete-recovery.json` 完成标记。途中失败会明确报告未完成，并保留隔离目录用于检查；不得把没有完成标记的目录用于恢复。

此入口用于重建并验证删除前的数据。它不改写原数据库中的绝对 rollout/cwd 路径，不执行原地覆盖，不启动 Codex，也不保证该目录能直接 Resume。需要从隔离材料合并回原生 home 时，应另行设计冲突检查、恢复前快照及原生验证。

## 实现与边界

原生源目录在快照验证前只被读取：SQLite 的 DB、WAL 和 rollback journal 先复制到快照私有暂存目录，再使用 SQLite backup API 生成可独立打开的数据库；源文件在捕获前后进行指纹比较，不直接把裸 DB 复制当作有效备份。manifest 在内容保存完成后原子发布，随后全部回读校验；Unix 新建目录链及数据库父目录同步，文件写入复用现有原子与同步原语。Windows 实际掉电、macOS/Linux 实机以及存储设备持久性仍需平台验收。

删除再次核对源指纹和写入者。rollout 暂存删除、共享 JSON 更新和 Desktop 项目状态均绑定到已验证预图，后续并发改写触发拒绝或补偿。SQLite 事务和跨文件补偿继续沿用现有机制。Core 提交后的 Desktop 缓存清理仍是独立事务；失败返回部分完成及快照路径。

进程探测并非原生工具配合的独占锁，无法证明任意重命名的程序绝不写入。该补丁只为 Codex 删除接入专用快照包；没有迁移路径/schema，没有接入通用 Vault 对象存储、在线捕获或自动恢复。
