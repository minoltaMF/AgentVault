# 统一只读会话工作台

入口是侧栏「全局 → 全部会话」（`/all-sessions`）。第一步支持设置中的 Codex 与 Claude 两个来源；打开页面不会自动扫描，点击来源卡片可单独读取，顶部刷新可同时读取两个已配置来源。

## 当前行为

- 每个来源独立显示路径、读取状态、最近成功时间和失败原因。一个来源失败不会清空另一个来源，也不会清除该来源上次成功的结果；旧结果带时间提示。
- 列表按更新时间降序，每页 50 条。支持 Provider、完整项目路径、归档状态筛选，以及标题、首条消息、ID、路径搜索。该搜索不是全文索引；同名项目不按目录 basename 合并。
- 点击标题打开现有对话预览，保持筛选和列表位置。只读模式隐藏编辑、删除、分叉和编辑历史入口；复制 ID、路径与 resume 命令仍可用，不自动启动原生 Agent。
- UI 身份复用 Provider 与实际会话路径组合，避免跨 Provider 同 ID、Claude 同 ID 多个文件发生串选。
- 筛选保存在 URL。来源结果只在当前页面内存中保存，离开或重新加载页面需再次读取。设置中的源目录改变时清空旧数据并使旧请求失效。
- 来源读取是独立后台任务。页面显示发现文件、读取索引、读取文件等实际阶段，以及已发现、已处理和失败计数；发现与读取交替进行，不把当前发现数量当作最终总量，也不显示估算百分比。
- 「停止扫描」向后端发送取消请求，收到终态后才显示「已停止」。取消不会用未完成结果覆盖上次列表，可再次读取。离开页面会请求取消；启动响应较晚返回时仍会补发取消。断网时取消无法保证送达，重新进入并读取同一来源可接回仍在运行的任务。
- 状态查询失败显示「状态待确认」，保留任务 ID，提供重试查询和停止；不会直接当作扫描已结束或新建重复任务。
- 坏 JSON、缺失/不可读文件和不可遍历目录记录路径与原因，其他文件继续读取；结束时标为「部分完成」。失败详情最多保留 200 项，总数完整计入统计；目录失败也属于失败项。源目录或必需索引整体不可用时仍整体失败并保留旧列表。

## 实现边界

扫描任务复用现有 Codex 索引摘要、Claude 解析、归档解析和来源注记，旧 `list_sessions` 行为保留。没有迁移数据库、配置路径，也没有新增依赖或修改原生会话的写入逻辑。读取成功只表示本次扫描完成，不表示备份健康、完整索引或原生续聊可用。

本功能仍不包含 Pi、Registry/FTS、Doctor 诊断或后台自动刷新。任务在内存中保留，最多 4 个运行任务、16 个任务记录，仅淘汰已结束记录；同一 Provider 与来源的运行任务会被复用。运行中状态查询不复制完整会话结果，终态才返回结果。

新扫描入口逐文件先检查 JSONL 格式，再复用原解析器，可能发生两次读取；含坏行的文件整项报告失败，旧列表的宽松解析行为不变。取消在目录项、文件和行处理边界检查，不能中断操作系统正在阻塞的单次读取。当前计数针对 JSONL 文件，不代表数据库行数或读取字节数；大规模耗时与内存仍需独立基准验证。

下一步建议：合并 JSONL 验证与摘要解析为单次流式读取，并用固定数据集测量扫描耗时、取消延迟与峰值内存。
