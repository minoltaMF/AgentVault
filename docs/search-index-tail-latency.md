# 缓存正文查询尾延迟

本专项先测量，再优化。测试只使用临时合成来源，不接触用户会话；沿用首次索引、重启复用、单文件重建、命中预览偏移和源文件哈希断言。

## 复现与统计

```sh
AGENTVAULT_SEARCH_DIAGNOSTICS=1 node scripts/benchmark-workbench-index.mjs \
  --cli /absolute/path/to/release/cc-sessions \
  --sessions 1000 --messages 100 --body-length 1024 \
  --warm-samples 30 --warmup-samples 3 --output /absolute/path/to/result.json
```

PowerShell 中先执行 `$env:AGENTVAULT_SEARCH_DIAGNOSTICS='1'`，CLI 使用 `.exe`。开启诊断只增加返回状态中的可选 `diagnostics`，不记录查询词、文件路径或正文。未设置时不采集阶段时钟；普通用户界面不展示这些内部指标。

每个来源建立独立索引。稀疏助手命中、无命中、用户消息命中三类查询，分别先暖身三次、正式采样三十次，每轮轮换查询顺序。暖身保留原始值，但不计入分位数。P50/P95 使用最近秩（nearest-rank）：排序后取第 `ceil(n × p)` 个实测值，同时保留最大值。30 次样本的 P95 仍只有极少尾部观测，不能代表稳定生产分位数或 SLA。

HTTP 耗时包含启动请求、轮询及调度，轮询间隔为 25 ms；小于该尺度的变化不作为可靠收益。每次命中后的预览验证在搜索计时之外。诊断总耗时仅覆盖服务端搜索执行，不包含线程启动、HTTP 或轮询等待。

阶段包括摘要加载、范围选择、外层路径校验、来源校验、身份与游标查询、重建写入、FTS、事件加载与匹配、最终指纹复核。来源校验和身份查询各按实际执行次序拆成两段后累加；重建写入包括原文件解析及事务提交。各阶段不重叠，未归类调度和状态维护使阶段之和可能小于总耗时。

## 适用范围

本组沿用 Qoder、WorkBuddy、Grok、Pi，每来源 1,000 会话 × 100 消息 × 1,024 正文字符。它反映大量普通会话下的显式范围缓存搜索，不覆盖超长单会话、短词全库匹配、大量命中、自然语言分布或网络磁盘。保留文件路径、指纹、可见性及取消检查；不得为降低延迟放松这些约束。

构建与测量不并行执行；OS 文件缓存不清空，宿主负载未受控。分析同时查看 HTTP 原始样本及诊断阶段，区分程序开销与轮询/调度波动，不只比较平均数。

## 2026-10-06 前后结果

使用同一台 Windows 11 ARM64 虚拟机（6 个逻辑 CPU、约 9 GiB 内存），执行 x86_64-pc-windows-gnu release CLI，来源和派生库位于本地临时磁盘。基线是提交 `accda1c` 加相同的可选计时插桩，未包含查询优化；构建后冻结二进制。前后均开启诊断、每轮共 360 个正式查询样本，保留全部慢样本，不截尾、不筛选“较好运行”。运行跨日，不能排除宿主负载差异。

| qoder | user | 1.20 | 0.88 | 1.82 | 1.28 | 2.08 | 1.38 |

### 定位证据和改动

原身份查询的计划为 `SCAN native_sessions USING COVERING INDEX`，完整四元身份键的计划为 `SEARCH ... (machine_id=? AND source_instance_id=? AND provider_id=? AND native_session_id=?)`。独立只读 Python/SQLite 微测中，1,000 次定位五轮约 132–146 ms 对 9–10 ms；该 ARM64 微测只确认 SQL 路径差异，不等同于 x86_64 CLI 的端到端收益。

基线 Qoder 最慢一次 HTTP 为 2,351 ms，服务端为 2,303 ms；其中来源校验 1,430 ms、外层路径校验 369 ms、身份/游标 174 ms、FTS 244 ms，说明该慢样本主要发生在服务端检查阶段，不能仅归因于 25 ms 轮询。

本轮只改两项：使用现有完整身份索引；显式索引来源省去重复外层路径校验，内层仍在打开文件前执行同等路径边界检查。稀疏查询三十个样本的阶段中位数如下，单位毫秒；阶段分位数不可相加当作总耗时分位数。

| 来源 | 旧身份/游标 | 新身份/游标 | 旧外层路径 | 新外层路径 |
| --- | ---: | ---: | ---: | ---: |
| qoder | 122.9 | 32.7 | 224.0 | 0.0 |
| workbuddy | 152.1 | 31.2 | 273.1 | 0.0 |
| grok | 141.3 | 45.7 | 298.7 | 0.0 |
| pi | 111.2 | 35.6 | 198.2 | 0.0 |

完整身份查询仍包含机器和 Provider，旧通用 API 与写入冲突保护保留。来源注册、Grok 可见性、文件指纹及最终复核仍执行；即使结果截断后只刷新文件，缺失或越界的原文件也不能由旧缓存授权。FTS 逐文件查询、事件物化和预览逻辑未改。

最终每个来源的首次索引、缓存复用、重启、用户/助手预览偏移、单文件重建、旧关键词消失及分阶段源文件哈希检查均通过。尾部样本仍会受文件系统、Provider 元数据和调度影响，不宣称消除所有卡顿；短词、高命中和超长单会话应另立数据集，不能从本组普通会话结果外推。

### Pi 异常后的相邻复测

因主对照出现上述长暂停，再按旧版→新版顺序各运行三类查询 × 30 次，另加各三次暖身，共增加 180 个正式样本。版本、数据规模、诊断和全部断言不变；原始对照未剔除任何数据，复测单列于同一结果文件的 `pi_recheck`。单位秒。

| 查询 | 旧 P50 | 新 P50 | 旧 P95 | 新 P95 | 旧最大 | 新最大 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| sparse | 1.11 | 1.06 | 1.40 | 2.40 | 1.42 | 3.27 |
| absent | 0.96 | 0.90 | 1.31 | 2.31 | 1.47 | 2.71 |
| user | 1.06 | 1.07 | 1.55 | 1.58 | 1.62 | 1.73 |

复测只说明该轮表现，不能证明原先 29 秒暂停已经根治。已确认的代码收益是减少完整身份定位和重复外层校验的工作；未确认的部分是偶发全局变慢的具体系统原因，仍应保留阶段诊断进一步观察。

复测的 90 个正式样本合并查看，身份/游标阶段中位数由 114 ms 降至 41 ms；但来源校验中位数由 449 ms 升至 600 ms，FTS 由 219 ms 升至 274 ms，最终指纹由 20 ms 升至 28 ms。新版最慢样本 3.27 s 中，来源校验占 1.91 s，FTS 占 0.88 s。多个未修改阶段同时变慢，说明仅凭整次查询分位数不能归因到此次代码；也不能据此排除回归或断言宿主是原因。Pi 的尾延迟仍是未解决项，后续应在同一批夹具上交替运行版本，细分来源校验内部耗时并记录系统 I/O 与调度，再决定是否继续优化。
