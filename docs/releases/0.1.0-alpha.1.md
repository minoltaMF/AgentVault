# AgentVault 0.1.0-alpha.1 internal alpha

发布日期候选：2026-09-08

这是 AgentVault 第一轮架构工作的内部验收版本，不是公开稳定版。它以 cc-sessions commit `1c912b2bb35e328881f543dfef1eeb5ff510f2bf` 为兼容基线，保留上游 MIT 许可证、包名、binary 名、bundle identifier、应用数据目录、配置路径和现有数据库 schema。

## 本轮可验收内容

- Cargo workspace，以及独立的 `vault-io`、Provider、registry、resume、vault、recovery、git-context、health、app-service 和 WorkBuddy overlay crates。
- Claude、Codex 与 Pi 的只读发现模型、capability、canonical identity 和 source cursor。
- Unicode/短查询/trigram 搜索契约、原生 ResumePlan 与 cwd mapping。
- immutable snapshot manifest、content-addressed object/chunk store 和只读 snapshot verification。
- deterministic Recovery Capsule、Git checkpoint context、Provider Doctor、Recovery Inbox 与 WorkBuddy overlay 的库级实现。
- 11 项 crash、race 与兼容 restore 安全矩阵。

上述新 crate 多数尚未接入继承的 Tauri/CLI 业务路径。本版本用于验证架构边界和数据安全原语，不能被描述成完整的新 AgentVault 产品流程。

## 数据安全边界

- 新 Provider 发现、Doctor、Git context、Inbox 和 WorkBuddy overlay 默认只读；测试只使用临时目录、脱敏夹具或内存数据库。
- 不迁移任何应用数据位置、配置路径或 SQLite schema。
- 继承界面仍包含 cc-sessions 原有的编辑、删除、导入、恢复、移动和修复能力；internal alpha 使用者应把这些视为兼容功能，而不是新 Vault 的默认写入策略。
- 新 Vault 尚未提供 provider-aware restore。不要用库级 manifest/object store 测试结果推断真实 Provider 已可从新 Vault 自动恢复。
- 任何真实写操作前仍应退出可能写同一 Session/SQLite 的原生应用，并保留独立备份。

完整的已覆盖与未覆盖故障场景见 [crash、race 与 restore 测试矩阵](../safety-test-matrix.md)。

## 更新渠道

Internal alpha 默认不配置独立更新源，也不会回退到 cc-sessions 的 Release API。设置页的手动检查会明确报告更新渠道未配置，不会下载或安装上游 cc-sessions 制品。

只有受控构建显式设置以下编译时变量后，更新入口才会指向对应的 AgentVault GitHub 仓库：

```text
AGENTVAULT_RELEASE_REPOSITORY=owner/repository
VITE_AGENTVAULT_RELEASE_REPOSITORY=owner/repository
```

Alpha 制品不应启用这两个变量；当前更新实现只读取 `releases/latest`，internal alpha 继续通过原分发渠道升级。

| Windows ARM64 宿主上的 x86_64 GNU 工具链 | 前端测试/构建、核心 workspace、Tauri 无桌面特性 lib，以及 CLI 构建和 `--help` 冒烟可运行 | 原生桌面链接和 bundle 未完成，不发布此宿主生成的桌面制品 |
| Windows x64 MSVC | release workflow 已配置 | 必须由 tag CI 构建并验证安装包；本提交未在该平台产出制品 |
| macOS Apple Silicon | release workflow 已配置 | 必须由 tag CI 构建；未签名、未公证前仅限内部测试 |
| macOS Intel | release workflow 已配置 | 必须由 tag CI 构建；未签名、未公证前仅限内部测试 |

本地 release commit 不创建 tag、不 push、不发布 GitHub Release。只有版本检查、安全矩阵和目标平台 CI 均通过后，才可以从该提交创建 `v0.1.0-alpha.1` 内部 tag；该 prerelease tag 的 workflow 只创建 draft Release，需人工审阅后才能发布。

## 已知限制

- Provider SDK、registry/search、resume、Vault、Recovery、Doctor、Inbox 和 WorkBuddy overlay 尚未接入旧 Tauri/CLI 主路径。
- 固定 4 MiB append-only JSONL 分块捕获、SQLite online backup、snapshot DB reconcile、startup watcher reconcile 与新 Vault restore 尚未实现。
- 性能目标尚未在 5 万 turn、10 GB 历史和 20 MB Session 的规定数据集上完成基准验证。
- npm 基线审计仍记录 1 个 low、1 个 high；本提交不升级主要依赖。
- Vite 生产构建仍有 `vendor-charts` 超过 500 kB 的既有体积警告。
- 桌面安装包尚未完成签名、公证和目标系统启动冒烟，因此仅能称为 internal alpha source candidate。

## 内部验证与回退

```bash
npm ci
npm run release:check -- --tag v0.1.0-alpha.1
npm run test:safety
npm run build
cargo test --workspace --all-targets
```

回退应用程序时使用前一份内部构建，不覆盖或移动现有 Session。此版本没有数据目录或 schema 迁移；若测试过继承的写操作，应从操作前独立备份恢复，而不是用 Git 或安装包回滚用户数据。
