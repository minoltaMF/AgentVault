# AgentVault 0.1.0-alpha.18

为 Pi 缓存查询尾延迟增加可复现的同夹具交替对照和资源诊断，区分路径验证、注册锁等待和系统资源变化。

- 来源校验拆分为边界检查、来源标识、文件打开、元数据、指纹和适配器注册；Pi 注册进一步分离验证、锁等待和插入。计时为嵌套结构，父子不可重复求和。
- Windows 查询诊断增加工作线程 CPU/cycles、进程 I/O 和系统 CPU 差值；仅开启 `AGENTVAULT_SEARCH_DIAGNOSTICS=1` 时采集，失败值为 null，其他平台仍保留阶段计时。
- 新增 Pi AB/BA 交替基准，两个程序共享同一合成来源和派生索引，保留全部暖身和正式样本，校验缓存复用、命中定位及来源哈希不变。
- 新增只读 Windows 系统采样脚本与可重现旧热查询路径的实验补丁。

未改变搜索行为、路径安全约束、schema、原生会话和数据目录；只为现有 windows-sys 启用一个 API feature，未升级依赖。测量方法、结果与归因边界见 [Pi 尾延迟诊断](../pi-search-tail-diagnosis.md)。内核 ETW 采集被系统拒绝，系统队列与进程计数不等同于精确线程等待轨迹。

同夹具交替对照完成：180 个正式查询，三类 P95 均下降，85/90 组新版配对快于旧版至少 25 ms；无命中最大值仍略高。Pi 来源校验中两次路径验证占比中位数为 88.3%，注册锁累计耗时很小；最大 HTTP 样本的主要额外延迟在搜索工作线程之外，并伴随独立采样进程的采样间隔异常延长。原先 29 秒暂停未复现，不能声称该问题已根治。完整结果、361 次查询诊断和 254 条系统采样均保留。

验证通过：Rust 应用 lib 575/575、前端 100/100、统计 3/3、安全矩阵 12/12、前端及 release CLI 构建、Rust 格式与版本检查；交替脚本的小规模真实 API 验证及相同二进制拒绝验证通过。临时 Rust/编译器缓存曾缺文件，已恢复相同版本；最初共享 target 误复用同一二进制的运行已明确标记无效并中止，重新构建并核对差异后才采集上述正式结果。
