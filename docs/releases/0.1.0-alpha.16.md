# AgentVault 0.1.0-alpha.16

优化统一工作台首次索引写入成本和缓存搜索的重复工作，覆盖现有八个持久索引来源。

- 将单文件的机器、来源、会话登记及事件、游标、正文索引写入合并为一个事务；消息写入语句在文件内复用，减少重复编译 SQL。
- 新建来源文件不再执行无旧事件可删的全表扫描；已有文件重建仍替换自己的旧事件。
- 缓存摘要改为按来源批量读取，显式搜索范围按 Provider 和路径查找；复用当前数据库连接及查询语句，减少逐条查询和重复路径登记。
- 选中文件仍执行路径、身份、指纹和来源可见性校验；历史列表加载仍登记有效来源。新建失败完整回滚，更新失败保留原索引。
- 不修改原生会话、Registry schema、同步持久化设置、解析语义或兼容性标识；不新增依赖。

验证结果与同机前后对照见[性能基准](../search-index-benchmark.md)。基准使用临时合成数据，不代表真实语料、其他平台或原生安装体验；缓存查询样本不用于推断 P95。

四来源每来源 1,000 会话 × 100 消息：首次索引从旧版复测的 104.52–142.30 秒降至 32.99–47.60 秒，分别减少 60.7%–74.2%。缓存中位数在 WorkBuddy/Grok/Pi 上下降，Qoder 略升，不能宣称查询波动已全面解决。跨日样本、旧版复测和中间候选均保留，宿主负载未受控。

本地验证：Registry 21/21（含首次失败完整回滚、更新失败保留、身份冲突和多文件事件隔离测试），应用 Rust lib 570/570、前端 100/100、安全矩阵 12/12；最后的首次删除扫描修复另通过 Registry 全量及工作台索引 7/7 回归。前端和 release CLI 构建、Rust 格式、版本一致性检查通过。安全矩阵首次因未载入临时 Rust 工具链无法启动，载入已有环境后完整重跑通过。
