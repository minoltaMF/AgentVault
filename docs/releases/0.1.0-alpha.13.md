# AgentVault 0.1.0-alpha.13

统一工作台为 Codex、Claude 接入持久正文搜索索引，复用已有 Registry schema 与消息分类器，并移植 Wake 的 FTS 字面量转义和短词降级规则。

- 首次搜索建索引，后续按文件变化更新；其他十二个来源维持原扫描。
- 重启后可显式载入当前来源目录的已索引历史列表，保留筛选范围合同。
- 搜索显示复用/更新数量、最近写入时间，命中继续定位原始消息。
- 事件、游标、正文索引和缓存元数据原子提交；坏文件、半写入和取消不覆盖旧可用索引，也不把旧命中作为本次成功结果。
- 展示结果达到 100 条后仍完成当前范围的索引检查。
- 原生会话始终只读，不新增 watcher、MCP、其他来源持久索引或 schema 迁移。

数据位置、缓存范围、重建方法与限制见 [统一工作台](../unified-session-workbench.md)。索引含本机正文，不是备份；当前元数据列表是历史快照，新增会话及元数据变更须读取来源。

本地验证：前端 99/99、Rust lib 566/566、Registry 17/17、安全矩阵 12/12，以及前端构建、CLI 构建、格式和版本一致性检查通过。最后补充的取消与结果上限后刷新回归包含在索引定向测试 3/3 中。Rust WebUI + Edge 验证首次索引、重启后加载、重复搜索、中文命中及 1280×820 / 390×844 界面；测试源文件哈希不变，仅使用临时合成数据。

千文件压力检查使用约 105 MB 合成 Claude 正文（每条首消息约 105 KB），Windows debug 构建、临时本地目录、API 轮询计时。首次索引约 270 秒；匹配与结果上限优化后热搜索约 13 秒，1000 个文件全部复用、0 失败、展示上限 100 条。优化前相同轮询方式约 23 秒。此结果不是 release 构建基准或秒开承诺；长首消息元数据、全范围文件检查仍有开销，首次索引可取消。
