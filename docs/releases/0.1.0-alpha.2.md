# AgentVault 0.1.0-alpha.2 internal alpha

发布日期候选：2026-09-08

这是 `0.1.0-alpha.1` 的最小发布修复版本。它不新增业务功能、不迁移用户数据，也不改变 bundle identifier、Rust/npm package 名、CLI binary 名、应用数据目录、配置路径或 SQLite schema。

## 相对 alpha.1 的变更

- Windows 预发布 tag 只构建 NSIS 安装器，避免 WiX/MSI 对非纯数字 SemVer 预发布标识的限制。
- 正式版本 tag 仍使用现有默认 bundle targets；Linux 与 macOS 打包行为不变。
- 发布一致性检查会验证 Windows 预发布 NSIS 条件仍存在，避免后续修改重新引入同类失败。

`v0.1.0-alpha.1` 的 GitHub Actions 已证明前端、Rust、安全矩阵以及 Linux、macOS 和 Windows 应用编译通过；Windows 仅在生成 MSI 时因版本 `0.1.0-alpha.1` 的非数字预发布段失败。该历史 tag 和草稿 Release 不改写、不删除。

## 安全与兼容边界

- 本版本与 alpha.1 使用相同的只读 Provider、Vault、Recovery 和 WorkBuddy 架构边界。
- 不修改真实 Agent Session，不迁移应用数据，不改变已有数据库 schema。
- Alpha 制品仍未签名或公证，只用于受控内部测试。
- Windows NSIS 安装包和兼容 CLI/portable 制品必须由 tag workflow 生成；不得用本机非目标工具链产物替代。

完整功能范围、已知限制和回退要求继续参见 [alpha.1 发布说明](0.1.0-alpha.1.md) 与 [安全测试矩阵](../safety-test-matrix.md)。

## 发布验证

```bash
npm ci
npm run release:check -- --tag v0.1.0-alpha.2
npm run test:safety
npm run build
cargo test --workspace --all-targets
```

预发布 tag 的 workflow 只创建 draft prerelease。必须确认所有目标平台任务成功、资产属于同一 tag 且名称与架构正确后，才可人工发布。
