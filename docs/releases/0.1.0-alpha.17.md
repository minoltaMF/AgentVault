# AgentVault 0.1.0-alpha.17

专项测量统一工作台缓存查询尾延迟，并按分段结果减少可避免的查询与路径检查。

- 基准新增交错重复采样、独立暖身、最近秩 P50/P95/max 和原始样本；统计测试纳入 `npm test`。
- `AGENTVAULT_SEARCH_DIAGNOSTICS=1` 可采集阶段次数及耗时，成功、失败和取消均保留最终诊断；默认不采集，不记录查询词、路径或正文。
- 索引会话定位使用完整机器、来源、Provider、原生会话身份，利用现有唯一索引；保留原通用查询 API 和写入身份冲突保护。
- 显式索引搜索省去外层重复路径检查，仍在打开文件之前由索引入口执行同等边界检查，并保留来源注册、可见性、指纹及最终复核。非索引来源沿用原检查。
- 不变更 schema、依赖、数据目录和原生会话文件，不改 FTS 匹配语义或以未验证缓存代替本次检查。

四来源主对照和 Pi 追加复测共保留 900 个正式缓存查询样本。主对照中 Qoder、WorkBuddy、Grok 的三类查询 P95 均下降；Pi 首轮出现 29 秒暂停，追加复测未复现该长暂停，但两类查询 P95 仍升高，不能宣称 Pi 尾延迟已改善。完整身份查询开销减少已由分段计时与查询计划证实，Pi 的波动原因仍待定位。

测量方法、前后结果及局限见[缓存查询尾延迟](../search-index-tail-latency.md)。本轮覆盖 Qoder、WorkBuddy、Grok、Pi 的合成普通会话；不代表所有机器、真实语料、短词大范围命中或超长单会话。

本地验证通过：Rust 应用 lib 573/573、Registry 22/22、前端 100/100、基准统计 3/3、安全矩阵 12/12，以及前端、release CLI 构建、Rust 格式和版本检查。新增回归覆盖完整身份键、关闭诊断/线程隔离/错误计时，以及热缓存下缺失或越界文件在搜索和只刷新模式仍被拒绝。临时 npm 曾缺失 node-gyp 文件，重新解压同版本 npm 10.9.2 后完整重跑通过，未改项目依赖或全局安装。
