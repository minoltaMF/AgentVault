# AgentVault 0.1.0-alpha.19

减少 Pi 索引查询中的重复路径校验：工作台边界检查与 Pi 注册之间的完整边界遍历由两次降为一次，保留打开前检查、打开后复查和最终指纹复核。

- 打开文件前仍执行完整 Pi 布局与路径边界检查，仅接受来源根目录 `sessions` 下的 JSONL 会话，拒绝越界、缺失、类型不符及 link/reparse 路径。
- 打开文件后，对来源根、各级父目录和叶子文件逐项重新检查类型及 link/reparse 状态，通过后才登记预览来源；此阶段不再重复 canonicalize。
- 首次校验结果由私有、单次消耗的 proof 传递，不跨查询缓存，不用历史校验替代当前检查。扫描、预览及需要重新解析正文时的校验继续执行原有逻辑。
- 查询结束时的最终指纹复核保持不变，其他来源的校验流程保持不变。

上述流程仍不是原子路径打开，不能保证消除所有 TOCTOU 竞态，也不代表历史 29 秒暂停已经修复。性能结论须以本轮同夹具交替测量结果为准。

验证结果：本地 Rust 578/578、前端 100/100、安全矩阵 12/12、基准统计 3/3 通过；前端与 release CLI 构建、格式及版本检查通过。新增校验后路径替换、取消及缓存不能授权非法路径的回归覆盖，并修复 Pi 测试夹具的并发命名碰撞。

性能结果：30 轮交替、180 正式样本全部通过；来源校验中位数 498.5 → 360.1 ms，三类查询 P95 均下降。76/90 组快至少 25 ms，12/90 组慢至少 25 ms，不保证每次查询更快。所有预热及正式查询均复用 1,000 文件，源文件哈希保持一致。详见 [实现与完整基准](../pi-path-validation-dedup.md)。
